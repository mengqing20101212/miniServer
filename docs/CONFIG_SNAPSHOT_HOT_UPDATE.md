# 整套配置快照与多节点热更

本实现参考整套 Tables 的组织方式，沿用当前 Excel 工具，不依赖 Luban。
修改生成的 Manager 必须同时修改 ParserExcelConfig 模板。

## 运行时快照

每次准备重新加载全部表，创建独立的 ConfigSnapshot，解析完成后统一执行 Manager.afterLoad。
getInstance 查表入口保持不变，内部读取任务固定快照中的表。
PersistenceScope 自动建立 ConfigScope，嵌套操作继承同一快照。
Game 玩家执行段、协议路由、GM 控制器、Scene 操作均使用现有任务边界。
Scene 本地 submit/query 显式传递调用方快照，避免排队或换线程后混用版本。
长期协程每个实际执行段获取快照，跨执行段需要业务自行明确规则；不把 ThreadLocal 当作跨线程上下文。

全局只保存当前快照及待切换快照，不保留历史快照 Map，不复用 A/B 对象，不延时 clear 旧表。
任务持有的旧引用自然活到任务结束，之后由 GC 回收。配置记录及集合按只读约定使用。
旧版本目录保留于磁盘用于恢复，不等于保留旧版内存快照。

## 发布与统一时间

GM 上传可以增量；PREPARE 以最后已提交的完整包为基线合成完整版本，冻结内容及 SHA-256。
首次发布以 GM 部署目录作为完整基线。上传、准备和提交不能并行操作同一协调器。
版本号限字母、数字、横线和下划线，不能复用已发布版本。
本实现部署一个 GM 发布协调器，不支持多个协调器同时写同一发布目录。

PREPARE 必须通过 targetServerIds 明确指定本轮相关节点（GM 页面填写逗号分隔的服务器 ID），不默认覆盖所有服务。
PREPARE 固定所选健康目标节点及其本次启动 bootId，节点下载相同完整包，
验证文件集合、摘要和现有解析校验后 READY。不会从各节点自己的旧目录拼接配置。
目标节点重启、离线、摘要错误或时钟偏差超过 2 秒时不能提交。
2 秒包含上报链路耗时，应在校时正常、网络稳定的部署环境发布。

全部目标 READY 后 COMMIT 取不早于当前时间 15 秒的统一时间（可采用 prepare 指定的更晚时间）。
决定先写持久文件，再通知 Nacos；Nacos 分别保存正式决定 config-active 和本轮通知 config-hot-update。
节点先持久化 COMMIT，再安排一次整体引用切换，分别上报 SWITCH_SCHEDULED 和实际 ACTIVE。
所有冻结目标 ACTIVE 后，GM 版本变为 PUBLISHED。GM 本身作为协调端不订阅业务配置切换，避免重启时依赖自身尚未启动的下载端口。

定时器、机器时钟、GC、网络都可能造成实际时间差，不承诺绝对同一毫秒或全局原子提交。
通用 Game→Scene RPC 不携带、不强制校验整套配置版本。目标节点可能不依赖本轮修改的表，不能因无关版本差异拒绝请求。
节点只处理目标列表包含自身的发布指令；未参与发布的节点在通知和启动恢复时均忽略该决定。
已经进入 Scene 本地队列的操作持有原快照，可以完成原版本操作；不建立按版本查询的历史缓存。
特定跨服业务如果要求一致配置，应另行明确相关表及业务协议，不能以全局版本比较代替依赖判断。

## 失败恢复

协调端文件默认位于 configPath 的同级 .config-publications/<环境>，
可用 -Dminiserver.config.publishPath 覆盖根目录。publication.json 保存当前阶段、完整包、目标及状态；
committed.json 保存正式提交包，下一轮 PREPARE 不覆盖正式决定。
目录必须使用持久磁盘，升级和容器重建不能删除。

节点目录默认 .config-versions/<环境>/<serverId>，
可用 -Dminiserver.config.statePath 指定该节点专属目录。每个版本独立目录，不覆盖原部署文件。
committed.json 保存已接受决定，采用强制刷盘和同目录原子替换。
Linux 同时刷目录项；Windows 文件系统不支持目录 FileChannel，文件内容强制刷盘。

GM 和节点每 5 秒查询/重发，恢复丢通知、失败上报和重启后的决定。
提交前失败继续用旧版，可以通过 /api/config-hot-update/cancel 取消后新建版本准备。
提交后禁止取消；下载或加载失败暂停该节点新业务，扫描重试，恢复成功后开放。
迟到 COMMIT 进入暂停及追赶流程，不能假装已在过去的统一时间成功切换。
启动恢复发生于监听端口和注册 RPC 节点前；无法确认或加载正式版本则启动失败。
本地已校验的完整包可以在下载服务不可用时恢复，否则必须重新下载。

回滚配置按新的发布版本协调进行，不会回滚已经发生的扣费、发奖等业务结果。
新旧节点不能混用新协议上线，首次部署须统一升级；增删字段或改变结构仍需配套代码发布。
LOCAL_CONFIG 模式继续使用部署配置，不连接线上热更流程。

## 验证

自动测试覆盖整套原子切换、任务固定旧版、加载失败不影响当前版、二次热更不复用旧对象、
固定节点实例 READY、时钟/摘要拒绝、持久提交决定、真实本地 HTTP 下载及本地包重启恢复、
非目标节点忽略热更决定。测试不能替代真实多机器时钟、Nacos 故障和网络分区演练。
